# Literature search methods and log

Search date 21 November 2026 (Europe/Moscow). [Literature review](README.md) · [Source notes](sources.md) · [BibTeX](references.bib)

## Review method

This is a focused exploratory review to inform an experiment. The question is whether an NVIDIA RTX GPU can execute an independent tensor-heavy workload during sustained conventional shader arithmetic, and whether existing work measures the cost to rendering. Searches also covered controlled compute-only experiments, shared GPU scheduling, and official D3D12 integration and profiling references. No date cutoff was applied. Screening concentrated on accessible English-language sources and prioritized published papers, author manuscripts and first-party documentation.

For a coding agent, keep the research question, screening decisions, and claim-level evidence in versioned files. Give the agent permission to search and inspect original documents, have it record the exact queries and deduplicate by DOI, arXiv ID or title, and use paper section or figure locators for every consequential measurement. Follow references backward and use a citation index or targeted follow-up searches for newer work. Have a person independently check the smallest set of claims that will determine the experimental setup and the interpretation of its results. This workflow adapts search reporting and software-engineering citation-tracing guidance, with human oversight of AI-produced judgments. [PRISMA-S checklist](https://doi.org/10.1186/s13643-020-01542-z) · [Wohlin’s citation-tracing procedure, §3](https://www.wohlin.eu/ease14.pdf) · [Joint AI position statement, recommendations 4–5](https://pmc.ncbi.nlm.nih.gov/articles/PMC12577299/)

The agent used ranked web and scholarly searches, then checked publisher records, arXiv, author copies and official documentation. Duplicate mirrors were consolidated by DOI or title. The log keeps the productive discovery queries and identified citation trails. Searches returned ranked samples, with no exhaustive database export, stable hit counts, formal forward-citation sweep, or independent human screening. The results support a feasibility review. The apparent evidence gap cannot establish novelty or absence from the literature. The source notes identify where findings were checked against full text and where an abstract or vendor report was used.

## Coding agent tools

The built-in web and scholarly search tools were sufficient for this pass. No additional MCP, credentials, or installation was needed. For repeated or larger searches, the official read-only **OpenAlex MCP** is a reasonable optional addition. It supports citation traversal and returns the underlying OpenAlex Query Language query and a rerun URL. Hosted search requires authentication as described by the provider. Crossref’s REST API is useful for DOI metadata. Zotero can import the included BibTeX bibliography and keep references and PDFs in a shared library if the project grows. [Official OpenAlex MCP](https://github.com/ourresearch/openalex-mcp-server#openalex-mcp-server) · [OpenAlex API citation recipes](https://help.openalex.org/how-to/api-recipes/) · [Crossref REST API](https://www.crossref.org/documentation/retrieve-metadata/rest-api/) · [Zotero import documentation](https://www.zotero.org/support/adding_items_to_zotero)

## Screening decisions

| Candidate or citation trail | Decision |
| --- | --- |
| Combo §2, §6 and references 37, 39–40 → PilotFish, Tacker, and ISPA’s ICCD precursor | Retain. The latter two cover mechanisms for intra-SM compute overlap, and PilotFish defines a temporal baseline. Separate Combo’s tuned microbenchmark from its substitute OptiX workloads informed by game traces. |
| ISPA and Tacker | Retain. They are directly relevant to intra-SM co-location on real hardware using different mechanisms and overlapping author teams. Treat them as related evidence. |
| FlashAttention-3 and Kitsune | Retain for distinct mechanisms. FlashAttention-3 measures an overlapping fused algorithm on Hopper. Kitsune proposes scheduler changes for predictable co-residency. |
| CRISP §II and references 9–10 → NVIDIA GA102 and DLSS | Retain CRISP’s hypothesis and simulator evidence, and the GA102 example for real pipeline integration. Do not infer simultaneous execution under measured saturation from the reported frame time. |
| TensorRT-RTX and Nsight documentation | Retain as first-party API and measurement references. They establish supported submission and observations available to the profiler. |
| Atelico GPU Sharing Impact | Retain as a vendor-reported D3D12 renderer plus inference benchmark. Its renderer FPS and 1% lows give no rate for completed inference work in the same test. |
| Ho et al., *Improving GPU Throughput through Parallel Execution Using Tensor Cores and CUDA Cores* | Adjacent work. The study evaluates a simulated modified scheduler that offloads part of a single GEMM to conventional cores. It does not test independent rendering and background work on shipping hardware. [Author PDF, §§II–IV](https://sarajumohanty.github.io/Publications_Conferences/2022/Mohanty_ISVLSI_2022_GPU.pdf) |
| NVIDIA Unreal TensorRT-RTX style-transfer sample | Adjacent engineering example. Its Unreal Insights figures time enqueue tasks for a dependent post-process. Those figures do not establish overlapping pipeline execution. [Performance profiling, Figs. 2–3](https://developer.nvidia.com/blog/speed-up-unreal-engine-nne-inference-with-nvidia-tensorrt-for-rtx-runtime/#performance-profiling) |
| News, forum reports, performance marketing, and generic Tensor Core benchmarks | Excluded as quantitative evidence where they lacked a primary measurement of overlap, used no foreground workload, or had insufficient setup detail. |
